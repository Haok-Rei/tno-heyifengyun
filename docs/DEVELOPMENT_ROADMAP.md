# 合一风云后续开发规划

日期：2026-10-07。规划基线：GitHub版 `main / 8d77090`（V2.11）。

用户已确认：**优先深化现有路线与机制衔接。** 本文是后续开发方案，下面的任务均为拟开发内容；本轮完成代码与文档梳理，未实施这些游戏改动。

## 一、下一阶段希望达到的体验

玩家选择一条路线后，应该能回答三件事：这一阶段要解决什么；为什么采用这个办法；前面的选择怎样影响今天的合一。

开发主轴是把已有国策、决议、法案、地图行动、工作组和特色机制组织成连续的章节。保留原有路线身份、剧情分歧和TNO美术，逐章增强策略取舍和叙事反馈。

### 当前基础与主要机会

| 当前已有 | 下一步深化 |
| --- | --- |
| 各主要路线已有国策、地图、决议和法案的代表性关联 | 每条路线分章节配置关联，落实到具体剧情节点与地方后果 |
| 工作组能定期执行地图行动，并获得路线筹备成果 | 让成果影响改革落实、协商条件、选区组织等既有玩法；保留手动完成途径 |
| 多个国策已自动切换法案并通知玩家 | 明确哪些制度被改变、哪些安排继续存在，以及新制度实施后的反应 |
| 路线小游戏、随机事件、合一之光、结局统计和美术室 | 让这些界面讲述同一局游戏中发生的变化，增加跨章节和结局的回声 |
| 多槽存档、事件队列、回归检查和分体裁文案工作台 | 用可重放的章节样例保护联动逻辑，按样稿与事实审核扩充内容 |

这些判断来自当前代码梳理，不代表已完成全路线试玩。

## 二、开发路径的取舍

| 路径 | 能带来的变化 | 代价与适用时机 |
| --- | --- | --- |
| **A：现有章节联动精修，推荐** | 多数玩家都会经过的部分先变好，已有路线获得更清晰的目标和更多选择后果 | 需要先梳理状态和剧情时序，适合当前优先级 |
| B：先扩充新路线与结局 | 较快带来新的探索内容 | 同时增加联动、存档和美术维护量；安排在试点与现有主线完成后 |
| C：先重建技术底座或迁移引擎 | 为新的平台需求和表现形式重新组织开发 | 当前瓶颈应先通过章节改造和性能实测定位；在出现明确平台需求后单独评估 |

采用A；技术整理随章节推进，每个开发批次都交付可以游玩的完整成果。新增路线在第四阶段之后进入选题评估。

## 三、四个开发阶段

### 第一阶段：开局—联合革委会联动精修

**建议作为下一轮的正式开发范围。** 这一段连接多数路线，且地图控制、代表大会、团结与集权、工作组、法案和分歧同时存在，最适合建立样板。

将现有流程整理成三个章节：开局联络与动员、B3行动与接管、革委会协商与十字路口。章节名称用于开发组织；玩家通过现有事件、国策、路线指南和提醒了解阶段目标。

每章制作一份简洁的联动表：

> 剧情时点 → 既有国策与事件 → 可用决议和制度 → 地图/工作组的用途 → 特色机制中的反馈 → 保留到下一章的结果。

重点工作：

1. 明确开局动员行为与激进愤怒增长的因果，提示当前可做的行动及其代价；保证事件先后与B3行动吻合。
2. 让起义前的地方联络和组织成果在接管阶段产生后续反馈，例如联络顺畅程度、接管事件差分或组织资源继承。具体效果先对照原剧情确定。
3. 深化“公审杨玉乐 / 秘密妥协”已有席位和顾问后果，使差异延续至会议、地方落实和后续事件。
4. 联合革委会中的地图斗争、代表大会危机和团结/集权变化围绕当前分歧推进；保持十字路口到后续地区任务的操作连续。
5. 工作组成果进入本章实际问题，保留周期执行原地图行动的方式；进度、停工原因、下一次执行时间清楚可见。
6. 补齐关键事件与三个阶段的合一之光反馈；提示玩家“发生了什么”，玩法说明留在效果与引导区域。

**发布验收：**

- 从新开局能连续进入民主与真左两个出口；常规玩法可完成，章节中有可选择的推进方式。
- 同一关键节点的不同选择，至少在下一章的事件、席位/地区状态或可用行动中留下可辨认的差别。
- 国策完成、法案切换、危机、事件与工作组结果有明确的生效顺序；同一结果不会重复结算。
- 关键节点前后保存、读取后，事件选项、地区交互、工作组与路线判定一致。
- 新玩家能从游戏内得知当前目标及一般方向；精确路线判定保留在可主动展开的指南中。

### 第二阶段：逐路线深化各自的玩法

先做与第一阶段直接衔接的民主、真左，再做杨玉乐、及第，之后推进豪邦、清洗/秩序各分支与狗熊。每批完成一至两条路线，做到阶段目标、玩法、正文和场景一起验收。

下表列出拟深化方向，具体新增剧情需先核对路线事实与原稿：

| 路线 | 应继续突出的既有体验 | 可深化的联动 |
| --- | --- | --- |
| 民主 | 议会、选举与制度建设 | 地区关切与实际法案影响选情；工作组持续经营选区；选前承诺在胜选后出现兑现与取舍 |
| 真左 | 政治局、做题改革与基层落实 | 法案决定试点办法；地区任务和工作组形成落实成果；改革界面与事件反映实际推行情况 |
| 杨玉乐 | 办公桌、校内秩序与教师关系 | 文件处理改变地区事务与教师协作；旧办公桌事件按阶段和条件出现差分；决定留下后续文件反馈 |
| 及第 | 教辅产业、经营与学校转型 | 生产、供应、测评制度与学生状态互相牵动；工作组承担地区产销任务；经营成果具有校园层面的代价与收益 |
| 豪邦 | 公社试点、协调与继承 | 公社在不同地区落实，地方成果影响谈判和制度选择；组织延续进入后续阶段 |
| 清洗与秩序各分支 | 整编、戒严、情报与处置 | 地图任务、法案与处置方式改变后续秩序状态；区分不同分支的行动逻辑和结束条件 |
| 狗熊 | 解构、礼堂动员与网络机制 | 网络/礼堂任务与相关制度、国策节点接续，保留该线独有叙事节奏和玩法趣味 |

**每条路线的共同验收：**

- 先标出2—3个关键章节，逐章检查至少一条完整的跨系统联动；根据实际长度调整章节数。
- 至少两处关键选择产生后续反馈；反馈可以共用主线节点并改变文本、地方状态或选项，无需大量新增平行国策。
- 特色机制的阶段成果影响国策/事件推进条件、实施质量或结局差分，且界面说明清楚。
- 工作组有明确的路线用途与自动执行收益；主动地图操作仍有适用场景，重复操作量低于改造前。
- 制度收益有相应成本或局限；单一固定法案组合不会覆盖所有路线目标。
- 同路线选择不同办法，可以形成不同的校园状态；同类事件有阶段条件、冷却或记忆，避免相同正文频繁出现。

### 第三阶段：叙事回声与多周目探索

这一阶段强化“这局是我走出来的”与“下一局值得试另一种办法”。文案准备从第一阶段就开始，结算与跨局功能在路线联动稳定后集中扩充。

- **人物与制度有时点。** 整理路线时间线、人物身份、当前立场和已发生事实；人物简介与国家精神随重大转折更新，保留该时点应有的信息。
- **前面的决定会回来。** 选择少量重要人物、地区和制度，让前期决定在后期事件中得到回应；优先有明确因果的节点。
- **结算讲清实际结果。** 保留年份、毕业估算、卷子使用、社团活动等简洁指标，附少量与路线及玩家选择相关的结果描述。毕业数字按实际经过的毕业季估算，标明估算口径。
- **路线提示分级。** 复用路线指南，区分当前目标、剧情方向与精确条件；完整结局名称和攻略条件由玩家主动查看。
- **美术室完善收集。** 给关键CG、超事件与结局提供解锁来源及分类；存档、结局和美术收集支持备份/恢复，覆盖更换设备或清理浏览器的需求。

验收重点：正文事实与触发时点一致；至少若干关键前期选择能在后期找到回应；玩家能了解自己获得的结局，并知道仍有其他探索方向。

### 第四阶段：统一表现、性能与发布质量

美术跟随前两阶段的章节产出，此阶段集中处理全局一致性和剩余缺口。

- **合一之光：** 共用透视、景深与环境结构；按路线制度、重大节点和地区状况细化差分。人物与物件的悬停勾线随动画移动，分层遮挡一致。保持观赏性质与无buff的动态国家精神设定。
- **UI：** 统一国家界面、决议、国策树、特色机制的边框、文字层级、效果颜色与弹窗层级；先保证空间和阅读，逐界面验收。
- **资源：** 为重要国策分支和国家精神优先补齐有辨识度的贴图；记录素材来源与复用关系。关键故事节点先完成专属图像和音效。
- **声音：** 按叙事节点配置合适音效，复核超事件与背景音乐的暂停/恢复及音量规则；减少长时间游玩中的重复声响。
- **性能：** 测量冷启动、开国策树、日推进与场景动画；按测量结果做特色界面按需载入、重绘控制和资产压缩。对代表性小屏窗口及低配置环境检查帧耗时和阅读可用性。
- **发布：** 统一版本号、更新说明、开发文档和构建入口；维护旧存档迁移清单与可回退的上一版本。

验收按代表性界面与路线做截图对照；优化前后采用相同存档、视口和测量方式，记录变化。数值性能目标在取得当前基线后制定。

## 四、联动应怎样落地：两个例子

以下为方案示例，细节待剧情核对与平衡，不替代现有路线判定。

### 例一：联合革委会的两种处置

公审和妥协已有席位与顾问效果，可以继续延伸：

1. 国策完成后按当前剧情改变席位、顾问与相关制度，展示对应事件。
2. 在会议和地方任务中体现不同合作条件：公审后的责任归属、妥协后的旧教务协作，分别提供对应事件与落实路径。
3. 工作组执行同一种现有地方行动时，根据本章已采用的安排产生适合的反馈；结果可影响地方落实或后续协商。
4. 十字路口保留既有分歧逻辑，通过人物态度、会议与路线提示提前说明正在形成的方向。
5. 进入下一路线后，少量重要事件与合一之光继续反映这一处置的后果。

### 例二：民主线的选举与执政

保留现有60天大选、各派宣传工作组和地区选情展示。深化时先确定六个选区与地图子地块的汇总关系，然后赋予地区有依据的议题差异。

制度调整、地方行动和持续宣传共同影响支持；胜选后，部分既有国策与事件回应选前采取的办法。这样，选举成果和执政任务能够接上，工作组的地区成果也能保留下来。

## 五、文案工作流：继续使用，强化编辑判断

沿用 [文案工作台](writing/README.md)，主参考为已有TNO原文；及第线中用户认可的文本作为项目内样稿。

每批按以下顺序处理：

1. **事实卡：** 体裁、路线、时点、人物身份、触发条件、选择前后、必须保留的信息。
2. **匹配样稿：** 按事件、新闻/通告、人物简介、国家精神分别选参考；先核对样稿适用于何种内容。
3. **小批生成：** 按同体裁、同路线组稿，使用现有缓存与调用预算；生成结果保留原稿对照。
4. **编辑审稿：** 检查事实、语气、叙事主体、有效信息、重复句式和选项前后，明确接受、修改或保留旧文。
5. **界面校对与入库：** 检查篇幅、换行、效果分区与时点差分，保存逐条修改记录。

先完成少量代表性样稿，确认质量标准后扩大批次。字数只用于提示信息不足；重写优先级为关键联动事件、明显缺信息的短文和反复出现的随机事件。剧情提醒不混入小说正文，特质与数值由专门区域展示。

## 六、技术整理随章节实施

| 工作 | 目的 | 实施边界 |
| --- | --- | --- |
| 扩充 routeOperations 为章节关联表 | 明确每章国策、决议、法案、地图与特色机制怎样接续 | 复用现有统计与状态，新增结果有真实用途才保存 |
| 按路线整理国策数据与完成行为 | 降低修改大文件时跨线误改的风险 | 先建立代表性状态快照与行为检查，再逐路线移动 |
| 逐段抽取每日结算，支持固定随机来源 | 重现事件时序、危机与平衡问题 | 优先抽取试点章节；对照相同初始状态的原行为 |
| 完善事件身份、一次性效果与存档迁移 | 国策完成、排队、关闭和读档都可正确恢复 | 复用现有事件队列及恢复机制，逐类补覆盖 |
| 统一发布版本和资料 | 玩家、开发、GitHub与Cloudflare记录可对应 | 自动生成或检查显示版本；文档标明基线与日期 |

章节记录要区分：可继承的历史结果、需迁移的制度、应结束的临时危机与国家精神。路线切换按这些规则处理，保留剧情需要的遗产。

| 顺序 | 任务 | 完成证据 |

| 1 | 梳理开局至十字路口的时序、条件和效果 | 三章联动表，明确现有规则与拟改动 |
| 2 | 保存代表性开局、B3、大会与分歧状态 | 可重复运行的检查场景，覆盖关键读档时点 |

| 5 | 延伸公审/妥协与大会的地方后果 | 两条对照流程有可辨认且符合剧情的差异 |

## 八、节奏与范围控制

- 以可发布批次排期，第一阶段一个集中版本，第二阶段每一至两条路线一个版本，后续叙事和全局优化分别发布。
- 每批先确定剧情事实、可玩目标和验收场景，再安排代码、文案和美术。工期在首批梳理完成后估算，本规划不承诺日历日期。
- 在关键节点检查失败、事件重复结算或旧存档无法恢复时，先完成该节点的修复再扩大范围。
- 第一阶段的成败以连续玩法和选择后果评价；第二阶段以各路线的独特体验评价；第三阶段以剧情回声和探索意愿评价；第四阶段以视觉一致性与实测可用性评价。
