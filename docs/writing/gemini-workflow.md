# 合一风云 Gemini 文案流程

以当前发行版为底稿。已有事件默认保留原文，特别是已被玩家认可的及第线正文和近期恢复的长事件。玩家报告了问题时先定位到句子。展开新路线时先确定分支与事实，再写对应体裁的稿件。

## 全文检索和排查

在网页版仓库目录运行：

```powershell
rg -n -F -e '王兆凯' -e '吕博涵' -e '周洪斌' -- src ../../hoi4-mod/heyi/localisation
rg -n -F -- 'election_outcome_event' src tests
npm run writing -- catalog
```

全文检索覆盖源码、其中的动态模板，以及 mod 本地化。UI 字样、标题、资源路径和历史别名也可能命中，先核对实际用途。目录的范围是可定位的静态事件正文、通告、人物和国家精神，保存到 `.writing-work/catalog.json`。当前收录 **576** 项，包括 490 条事件、6 条通告、34 篇人物和 46 条国家精神。动态模板、界面字样、国策说明和结局仍可通过源码搜索，缺少静态目录项时直接定位原定义。目录推测的路线和体裁需要用触发代码核对。

按路线和阶段逐批排查。优先处理错误报告、改动区域及同一人物、时间或机制的跨文件引用。需要系统巡检时按目录 key 分批，记录每条 `keep`（保留）、`fix`（有证据）、`check`（缺资料）或未审状态。把同一作品的日常和大结局分开审，有复用的场景先核对它们是否本来就处在不同时间。

## 生成 MCP 审阅包

```powershell
npm run writing -- gemini-packet --keys election_outcome_event,pan_despair_chain_2,wu_flavor_shiji_notes
```

命令只在 `.writing-work` 生成 JSON。运行结果给出路径、输入字符数和请求哈希。Codex 读取包内 `request`，原样传给 MCP 的 `gemini_write_text`。选择器支持事件 ID 或目录 key，遇到同 ID 有多个阶段时用 key。首批建议 3–6 条。只在结论依赖回调而材料不足时加 `--context`，或单独补一段实际调用条件。比如选举天数需要同时核对正文和选举流程，单凭名称或国策时长无法裁决所有叙事中的时间。

试跑可在 MCP 调用里显式传 `model: "gemini-3.5-flash-lite"`。把返回模型、请求哈希、日期、耗时及原始响应记在本地。重跑同一个包时可直接复用已存的响应。源码、核对依据或提示词变动后重新出包。把返回的 `text` 字段存成文件，再检查每个 key、结论、原稿和引文：

```powershell
npm run writing -- gemini-check --packet .writing-work/gemini-请求哈希前16位.json --response .writing-work/gemini-审阅结果.txt
```

命令兼容单个 JSON 代码围栏。缺项、重复 key、旧稿或无法唯一定位的修订引文都会使检查失败。事实是否成立仍需人工核对。MCP 目前不返回 token 用量，耗时与输入字符可实测，费用和服务端缓存命中率留空。

`fix` 只改能证明错的那一处，可保留原版镜头和收束。把原句与依据放在同一份对照稿。举例来说，「三十天」改「六十天」时保留竞选队伍疲惫、传单落在操场等其余情节。若人物、先后顺序或选项效果没有证据，把问题标为 `check`。

## 有目标地润色与起草新路线

先写剧本表，一条记录包含：

| 字段 | 写入内容 |
| --- | --- |
| 节点 | 事件 ID、路线、前置条件和所处阶段 |
| 信息状态 | 此时玩家、角色及发布者分别知道什么 |
| 场景 | 谁想完成什么，哪一次行动或发现推进情节 |
| 机制 | 各选项的结算结果、后续节点和仍待决定的事 |
| 体裁 | 事件、新闻、人物、国家精神，及对应参考 |
| 事实出处 | 国策、状态定义或事件文件与行号。待定字段明确标记 |

先核对各条分支能否到达，再以一条关键事件试写。使用本项目内及第线及经整理的 [体裁观察](reference-study.json) 做风格锚点。剧情事件靠视角和行动推进，公告先交代通告方与状态，人物简介体现当前身份，国家精神解释制度如何运转。新闻参考缺口沿用既有规则。大事件保留必要的场面和冲突，短提示按其功能写。

执笔请求只给一条已核准的事实卡，输出标题、正文和按钮，复杂新路线在同一阶段先写 1–2 条。审稿另发一轮，给事实卡及旧稿与新稿，不附执笔者的自评。核对体裁、人物知情范围、已发生与待选择的边界，检查有无删去关键情节。文风意见放在待讨论栏，允许结论为保留原稿。模型输出放入试稿，游戏文件中的字符串、事件 ID、选项函数和触发条件由现有 [入库流程](README.md#审稿与入库) 处理。新增路线先审触发与存档方案，再由开发者实装，分别检验可达性、读档及选项结算。

## 本轮试跑

- MCP 配置的快速档 `gemini-4-hydrogen` 有一次成功返回校验和试写，端到端约 40 秒。三个受控审稿样本分别正确标为修正、保留、待核实。首稿把内部通告写成了场景叙述，并误把开发标签「路线」写进正文。随后两次调用返回 503。
- 显式请求 `gemini-3.8-flash` 两次均返回 503，本次尚未测得其成功时延。模型目录与本机可用性分别核对。 [Google Gemini 模型目录](https://ai.google.dev/gemini-api/docs/models)
- `gemini-3.5-flash-lite` 约 10 秒审完 3 条真实记录，输入约 2,058 字符，对三条均建议保留。它接受了目录将绝望线误标为通用的元数据，已修正这处归类。跨版本检索另发现网页人物显示名为「时纪」，mod 部分正文仍用「时稷」。这类差异需要给模型提供双方正文与最新版人物表才可审定，头像文件名可单独核对。
- 同一模型约 8 秒返回新路线通告试稿，体裁比混合请求准确。稿子末尾加上了等待进一步指示的安排，超出事实卡，校对时删去即可。试跑结果留作开发参考。
