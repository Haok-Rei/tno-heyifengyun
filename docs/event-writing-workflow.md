# 《合一风云》叙事文本工作流

这份流程适用于事件、随机事件、人物简介与国家精神。参考材料是仓库外层 `文本/` 中的 TNO 事件、国家精神译文，以及游戏现有及第线《无限螺旋》系列。学习其**人物视角、制度如何落到生活细节、结尾如何留下余波**；不得照抄句子、套用人物或把每段都写成同一套阴暗修辞。

## 1. 先做“事实卡”，再写句子

为每个事件记录 `ID / 路线与阶段 / 触发条件 / 事件前状态 / 必须发生的事实 / 选择及数值效果 / 后续承接`。检查同一人物在本阶段是否仍在校、是否已经失势或死亡。标题与按钮也要对应实际效果。随机事件另记最近一次出现的同题材场景，避免靠改几个同义词重复播报。

锁定 `id`、条件、变量名、数值、选项数量和顺序。若叙事与机制冲突，先标出问题，由机制负责人确认；不可为了让文案顺手而偷偷改效果。

## 2. 挑选一个能看见的切口

每篇只确定一个主视角和一处主要场景：教室后窗、打印室、校门、走廊、教师办公室、食堂等。开头用**正在发生的事**进入，不以“随着改革不断推进”概述。中段让制度通过物件或动作显形，例如退回的申请表、磨损的印章、重打的成绩单。结尾保留人物的选择或代价，不重复宣告“这对校园产生了深远影响”。

篇幅按功能而定：提示事件约 120–220 字；一般随机事件约 180–320 字；路线节点约 250–500 字。重大剧情可以更长，但每一段要推进信息、人物或冲突。切忌为凑字数添入未经剧情支持的死亡、暴力、亲密关系或校外势力。

## 3. 每条路线有不同语气

| 路线 | 常见视角与物件 | 冲突核心 |
| --- | --- | --- |
| 开局与校方 | 值班表、课表、行政楼公章 | 秩序能否解释自身的代价 |
| 学生革命 | B3 楼梯、传单、临时会议 | 胜利后由谁替日常生活负责 |
| 民主 | 选票、议程、无人认领的具体问题 | 程序怎样兑现为决定 |
| 杨玉乐 | 保温杯、教案、评审材料 | 教师经验与考核体系互相挤压 |
| 及第 | 价签、合同、成绩屏、库存单 | 人被换算成可交易的业绩 |
| 吴福军 | 巡查记录、门禁、广播 | 可见的平静掩住了什么 |
| 狗熊 | 礼堂、投影、被改写的标语 | 玩笑何时开始伤及真人 |
| 吕波汉 | 名单、批注、检举箱 | 规则如何吞掉制定规则的人 |

不把任何路线写成一色好或一色坏。让支持者有实际理由，让反对者有具体损失。人物介绍则优先写其**做事方法、别人如何感受他、其弱点**，不要堆砌抽象立场。

## 4. 双人编辑与校对

长线创作可由一位“资料编辑”只读样例和既有路线，输出事实卡与禁改清单；另一位“执笔编辑”依事实卡写初稿；最后由不看初稿创作过程的“校对编辑”核对剧情、重复、UI 可读性。即使只有一人，也按这三个视角分三次完成。参考文本只用于分析手法，最终稿要独立原创。

校对时逐项检查：

1. 删除“极其、彻底、注定、深刻、宏大、史无前例”等无证据的强度词；尽量把“象征、体现、折射”换成动作。
2. 连续三篇是否都以“沉默”“一阵寒意”“谁也不知道”收尾；若是，换场景或换人物回应。
3. 对话是否像这个人会说的话，是否真的推进冲突；口号通常只在人物有动机喊时出现。
4. 所有数字、机构、地点、人物关系与事件触发阶段是否吻合；选项文案不可暗示不存在的效果。
5. 在游戏窗口按正常字号读一遍：首段能否独立交代处境，按钮是否好认，换行是否帮助阅读。

## 5. 验收与迭代

每批维护改写清单（ID、旧字数、新字数、事实核对人），优先处理少于 150 字、只总结数值结果、或与别的事件共用套话的条目。运行 TypeScript 检查和事件相关测试，并抽查早、中、晚三个阶段的展示。上线后收集玩家指出的重复事件与人物违和点，回到事实卡修订，而不是只润色单句。
